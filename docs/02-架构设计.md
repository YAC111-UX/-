# 知行职业学院排课选课教务协作 AI 智能体系统 · 技术架构设计

> 版本：v1.0（2026-11-06）｜依据：01-需求清单 + 需求评审全 A 结论
> 技术栈：FastAPI（异步）+ Python 3.11+ / SQLite / FAISS / JWT RBAC / 可替换 LLM API

## 一、四层架构图（文字版）

```
┌─────────────────────────── 入口层 ───────────────────────────┐
│ ① 学生/教职工聊天页（单页 HTML + 原生 JS，SSE 流式打字机）        │
│ ② 管理后台（服务端渲染，排课专员/教学质量专员/教务主任）           │
│ ③ 命令行原型脚本（阶段 1 本地验证用，后续退役）                   │
└──────────────────────────────┬──────────────────────────────┘
                               │ HTTPS / SSE
┌─────────────────────────── 服务层（FastAPI 异步）─────────────┐
│ 鉴权模块：JWT 登录 + RBAC 接口粒度校验（6 角色，教学质量专员否决权）│
│ 聊天模块：POST /chat（SSE 流式），携带最近 6 轮上下文             │
│ 知识库模块：文档上传/切片/向量化/停用/删除                        │
│ 管理模块：系统提示词模板（存库，改即生效）、试点暂停全局开关         │
│ 审计模块：会话筛选、高风险问答标记、工具调用日志查询                │
│ 草稿确认模块：调课草稿人工确认流（仅排课专员）                     │
│ 统一响应：业务错误码 + 中文可读错误信息                           │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌─────────────────────── 智能体编排层 ──────────────────────────┐
│ Agent 执行循环：模型决策 → 调工具 → 结果回填 → 再决策（最多 5 轮） │
│ 工具集（Function Calling）：                                    │
│   rag_search            制度文档混合检索（BM25 + 向量 top3）      │
│   check_prerequisite    先修冲突校验（结构化规则引擎，非 LLM）      │
│   check_room_conflict   场地/实训室冲突校验（规则引擎）             │
│   generate_adjust_draft 调课调整草稿（强制人工确认后才能落记录）    │
│   query_handover        历史交接单据查询                          │
│   notify_manual_fallback 人工兜底通知（4 类必转场景）               │
│ LLM 网关：统一封装，低成本档模型，供应商可配置替换                  │
│ 关键原则：冲突校验核心 = 纯代码规则引擎，不依赖 LLM                 │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌─────────────────────────── 数据模型层 ────────────────────────┐
│ SQLite（本地库）：用户/会话/消息/知识库/冲突回放/交接单据/工具日志   │
│ FAISS：制度文档切片向量索引；BM25：关键词倒排（双路混合检索）        │
│ 外部只读 API 适配器：教务系统 / 场地预约 / 学籍库                  │
│   · 实时查询优先，15 分钟增量同步                                 │
│   · 中断时降级用带时间戳快照，结果标注「基于 xx 时间快照」           │
│   · 学生选课数据不落本地库，实时透传                               │
│   · 课程新旧代码：官方映射表（只读）                               │
└──────────────────────────────────────────────────────────────┘
```

数据流要点：

1. 学生提问 → 服务层鉴权 → Agent 编排层先做意图判断 → 制度问答走 `rag_search`；冲突校验走规则引擎工具
2. 冲突校验结果 + RAG 引用 → LLM 仅负责"解释结果"，不负责"判定冲突"
3. `generate_adjust_draft` 调用前强制中断，草稿流式返回给排课专员确认
4. 每轮工具调用写入 `agent_tool_logs`，审计可完整回放

## 三、数据库表设计（SQLite）

### 1. users 用户账号

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 自增 |
| username | TEXT UNIQUE | 登录名 |
| password_hash | TEXT | bcrypt 哈希，不存明文口令 |
| role | TEXT | student / counselor / scheduler / quality / director / program_leader |
| is_active | TEXT | 1 启用 0 停用 |
| created_at | DATETIME | 创建时间 |

### 2. sessions 会话

| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | UUID |
| user_id | INTEGER FK→users | 归属用户 |
| created_at / last_active_at | DATETIME | 生命周期 |

### 3. messages 对话消息

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 自增 |
| session_id | TEXT FK→sessions | 所属会话 |
| role | TEXT | user / assistant |
| content | TEXT | 正文 |
| citations_json | TEXT | 引用来源：文件名 + 片段节选 |
| risk_flag | INTEGER | 高风险标记（如问绕过先修限制） |
| risk_reason | TEXT | 命中规则说明 |
| created_at | DATETIME | 时间 |

### 4. kb_documents 教务制度知识库文档

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 自增 |
| filename | TEXT | 原始文件名 |
| doc_type | TEXT | 培养方案/先修规则/场地规则/交接流程 |
| version | TEXT | 制度版本号 |
| status | TEXT | active / disabled（停用某版本）/ deleted |
| chunk_count | INTEGER | 切片数 |
| uploaded_by | INTEGER FK→users | 上传人 |
| created_at / disabled_at | DATETIME | 时间 |

### 5. kb_chunks 知识库切片（检索最小单元）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 自增 |
| document_id | INTEGER FK→kb_documents | 来源文档 |
| chunk_index | INTEGER | 切片序号 |
| content | TEXT | ≤500 字符切片原文 |
| vector_id | TEXT | FAISS 内向量 ID |
| enabled | INTEGER | 随文档停用联动 |

### 6. conflict_replay_records 选课冲突回放记录

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 自增 |
| business_no | TEXT UNIQUE | 业务编号（审计追溯键） |
| semester | TEXT | 学期 |
| check_input_json | TEXT | 校验输入（学生伪 ID，不含明文学号等敏感信息） |
| check_result_json | TEXT | 冲突事件列表（按事件数计数） |
| data_source | TEXT | realtime / snapshot |
| snapshot_at | DATETIME | 快照时间戳（快照时必填） |
| draft_id | INTEGER FK→drafts | 关联草稿（可空） |
| confirmed_by | INTEGER FK→users | 排课专员确认人 |
| created_at | DATETIME | 时间 |

### 7. handover_tasks 交接任务单据

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 自增 |
| business_no | TEXT UNIQUE | 业务编号 |
| version | INTEGER | 单据版本（每次改动 +1） |
| status | TEXT | pending / assigned / accepted / completed / escalated |
| title | TEXT | 摘要 |
| unresolved_items | TEXT | 未解决事项清单 |
| creator_id | INTEGER FK→users | 创建人 |
| assignee_id | INTEGER FK→users | 接手人 |
| accepted_at | DATETIME | 对方确认接手时间（=完成标志之一） |
| escalate_at | DATETIME | 超时自动升级教务主任的时间点 |
| escalated | INTEGER | 是否已升级 |
| created_at | DATETIME | 时间 |

### 8. agent_tool_logs Agent 工具调用日志

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 自增 |
| session_id | TEXT FK→sessions | 会话 |
| message_id | INTEGER FK→messages | 触发消息 |
| round_no | INTEGER | Agent 第几轮（1~5） |
| tool_name | TEXT | 工具名 |
| input_summary | TEXT | 入参摘要（脱敏） |
| output_summary | TEXT | 返回结果摘要 |
| duration_ms | INTEGER | 耗时 |
| created_at | DATETIME | 时间 |

### 9. drafts 调课调整草稿（草稿确认流专用）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 自增 |
| business_no | TEXT | 关联业务编号 |
| status | TEXT | pending_confirm / confirmed / rejected |
| content_json | TEXT | 原记录 + 待确认字段（建议必须显示原记录） |
| created_by_session | TEXT | 产生会话 |
| confirmed_by | INTEGER FK→users | 仅排课专员可确认 |
| confirmed_at | DATETIME | 确认时间（确认后才生成正式回放记录） |

### 10. app_settings 系统配置（提示词模板 + 试点开关）

| 字段 | 类型 | 说明 |
|---|---|---|
| key | TEXT PK | 如 default_prompt / pilot_enabled / fallback_prompt |
| value | TEXT | 模板正文或开关状态 |
| updated_by | INTEGER FK→users | 修改人 |
| updated_at | DATETIME | 修改即生效，禁止硬编码 |

## 四、第一周最小验证目标（MVP）

| 天 | 目标 | 产出 |
|---|---|---|
| D1 | 环境搭建：Python 3.11 + 依赖 + SQLite 建表 + `.env` 配置 | 可运行空项目 |
| D2 | 文档切片 + FAISS 入库：读取 3 份示例 md 制度文档（培养方案/先修规则/场地规则），500 字符切片向量化 | `vector_store.py` 跑通 |
| D3 | 混合检索：BM25 + 向量双路，取 top3 片段 | `retriever.py` 跑通 |
| D4 | LLM 网关 + 命令行问答脚本：拼装上下文 → 调 LLM → 输出带引用的回答 | `prototype_rag.py` 交互可用 |
| D5 | 验收自测 + 规则引擎骨架：用示例问题验证；先修冲突结构化校验伪代码评审 | 问答带引用、未命中时回复「制度中未找到对应说明，请联系排课专员人工核实」 |

MVP 验收问题（来自业务报告）：

- "我这门课有没有先修限制？" → 命中先修规则条文 + 引用来源
- "实训室维护期间课程冲突怎么处理？" → 命中场地区域规则 + 引用来源
- 陷阱题（知识库无答案）→ 必须输出兜底话术，不得编造

第一周不做的：Web 界面、Agent 循环、管理后台、外部 API 接入（用本地 mock 数据代替教务接口）。

## 五、关键架构决策记录（ADR 摘要）

1. **LLM 只解释不判定**：冲突判定 100% 由 `rules/` 纯规则引擎完成 → 识别率可控、LLM 挂了校验仍在
2. **LLM 网关抽象**：统一接口 `chat(messages, tools)`，供应商用环境变量切换 → 满足低成本可替换约束
3. **SQLite + FAISS 本地化**：试点期单专业数据量小，无需引入 MySQL/向量数据库 → 降低运维成本，90 天留存策略在应用层实现
4. **学生选课数据透传不落库**：学籍/选课数据经适配器实时查询，本地只存脱敏后的校验输入输出摘要 → 满足数据最小化要求
5. **提示词模板入库**：`app_settings` 存储，管理后台修改即生效 → 禁止硬编码
6. **草稿是独立表而非直接写回放记录**：确认链为「Agent 生成草稿 → 排课专员确认 → 落正式记录」，天然满足审计"人工改动 + 签核人"字段要求
