# 知行职业学院排课选课助手 · 用户端聊天接口设计

> 版本：v1.0（2026-11-06）｜阶段 4｜沿用 02-架构设计 的表结构与模块划分
> 范围：仅学生/一线教务人员问答入口；管理后台与 JWT RBAC 属阶段 5，本阶段预留挂载点

## 一、接口清单

| 方法 | 路径 | 用途 | 阶段 |
|---|---|---|---|
| POST | `/api/chat` | 提问，SSE 流式返回回答 | 本阶段 |
| GET | `/api/session/new` | 创建新会话，返回 session_id | 本阶段 |
| GET | `/` | 聊天页面（单页 HTML + 原生 JS） | 本阶段 |
| — | `/api/auth/*`、`/api/admin/*` | 登录与管理接口 | 阶段 5 预留 |

## 二、核心接口：POST /api/chat

### 请求

```json
{
  "session_id": "uuid-字符串，首次可为空（空则服务端自动创建会话并通过 SSE 事件返回）",
  "question": "我这门课有没有先修限制？"
}
```

参数校验：`question` 非空且 ≤ 500 字符；`session_id` 存在则必须能在库中查到。

### 响应：SSE 事件流（text/event-stream）

按发生顺序推送 4 类事件，前端按 `event` 字段分发处理：

| 顺序 | event | data 示例 | 说明 |
|---|---|---|---|
| 1 | `session` | `{"session_id": "a1b2…"}` | 首次请求时返回新会话 ID；已有会话也重复下发，前端统一覆盖保存 |
| 2 | `status` | `{"stage": "retrieving", "text": "正在检索教务制度与排课规则…"}` | 检索知识库时展示状态提示 |
| 3 | `delta` | `{"text": "根据《先修规则》第…"}` | LLM 流式增量文本，前端拼接实现打字机效果 |
| 4 | `citations` | `{"items": [{"filename": "先修规则.md", "excerpt": "未满足先修要求的课程，选课系统将直接阻断…"}]}` | 引用来源：文件名 + 片段节选（截断 80 字符） |
| 5 | `done` | `{"message_id": 123}` | 本轮结束信号，前端解锁输入框 |
| 异常 | `error` | `{"code": "2001", "message": "AI 服务响应超时，请稍后重试"}` | 任一环节失败即推 error 并结束流 |

SSE 报文格式示例：

```
event: status
data: {"stage":"retrieving","text":"正在检索教务制度与排课规则…"}

event: delta
data: {"text":"根据"}

event: done
data: {"message_id":123}

```

## 三、统一业务错误码（全项目沿用）

| 错误码 | 含义 | 中文提示（返回给用户看） |
|---|---|---|
| 1001 | 参数缺失/非法 | 请求参数不完整或格式有误 |
| 1002 | 会话不存在 | 会话已失效，请开启新对话 |
| 1003 | 提问超长 | 提问内容过长，请精简后重试 |
| 1004 | 请求过于频繁 | 操作太频繁，请稍后再试 |
| 2001 | LLM 超时 | AI 服务响应超时，请稍后重试 |
| 2002 | LLM 接口错误 | AI 服务暂时不可用，请稍后重试 |
| 2003 | 知识库为空/未就绪 | 知识库正在维护，请联系排课专员 |
| 5000 | 未知异常 | 系统开小差了，请稍后重试 |

非 SSE 接口（如 session/new）统一返回：

```json
{ "code": 0, "message": "ok", "data": { "session_id": "a1b2…" } }
```

失败时 `code` 为上表错误码，`message` 为中文提示，HTTP 状态码统一 200（业务码区分成败），便于前端统一处理。

## 四、后端处理流程

```
POST /api/chat
  1. 参数校验（1001/1003）→ 会话校验与创建（1002）
  2. 读取该会话最近 6 轮（12 条）消息作为上下文窗口
  3. yield status 事件（正在检索教务制度与排课规则…）
  4. 调用 RagPipeline：混合检索 top3 片段（复用阶段 1 核心模块）
  5. 持久化用户消息（role=user，含风险标记预留字段）
  6. 流式调用 LLM（复用 chat_with_llm，改造成流式版）：
     每收到一段增量 → yield delta 事件
  7. 拼装完整回答 + 引用来源 → 持久化助手消息（citations_json）
  8. yield citations 事件 → yield done 事件
  任意一步失败：yield error 事件并关闭流（已产生的部分回答仍落库，供审计）
```

业务红线（写入系统提示词 + 代码注释双保险）：
AI 仅做冲突提示与制度问答，不能执行选课、不能修改排课数据，回答末尾必须附引用来源。

## 五、前端交互设计（单页 HTML + 原生 JS，无框架）

```
┌────────────────────────────────────┐
│  知行职业学院 · 排课选课助手   [新对话] │
├────────────────────────────────────┤
│  （气泡列表，学生提问右/AI 回答左）      │
│  ┌ AI 回答气泡 ───────────────┐      │
│  │ 打字机逐字流式文本…           │      │
│  │ ── 引用来源 ──              │      │
│  │ 1.《先修规则.md》片段节选…     │      │
│  └────────────────────────────┘      │
│  ⟳ 正在检索教务制度与排课规则…（状态条）  │
├────────────────────────────────────┤
│  [输入框                    ] [发送]   │
└────────────────────────────────────┘
```

交互规则：
1. `session_id` 存 localStorage，刷新页面不丢会话；点"新对话"调 session/new
2. 发送后立即锁定输入框，收到 `done` 或 `error` 才解锁
3. 收到 `status` 事件显示状态条；收到首条 `delta` 时隐藏状态条、开始打字机
4. `delta` 到达即 append 渲染（自动滚动到底部）；`citations` 渲染为回答气泡底部的来源区块
5. `error` 事件在聊天区以红色气泡展示中文提示
6. 页面布局简单响应式：窄屏（手机）下输入栏固定底部

## 六、数据落库（沿用 02-架构设计 表结构）

| 时机 | 写入表 |
|---|---|
| 创建会话 | `sessions` |
| 收到提问 | `messages`(role=user, content, risk_flag 预留 0) |
| 回答完成 | `messages`(role=assistant, content=完整回答, citations_json) |
| 发生错误 | `messages`(role=assistant, content="[错误] 错误码+中文提示") |

阶段 4 暂不接外部教务 API（属阶段 6 Agent 工具），冲突类提问先走制度问答口径。

## 七、验收标准（阶段 4 自测口径）

1. 提问 → 页面先显示"正在检索教务制度与排课规则…"，再打字机流式输出回答
2. 回答底部自动展示引用来源（文件名 + 节选）
3. 刷新页面继续同一会话，上下文连贯（最近 6 轮生效）
4. 断网/拔掉 API Key → 红色气泡显示中文错误提示，不白屏
5. SQLite 中能查到全部会话与消息记录
