# 知行职业学院排课选课教务协作 AI 智能体系统 · 一页纸需求清单

> 版本：v1.0（2026-11-06）｜依据：《业务需求发现报告》36 条访谈事实 + 需求评审 10 问（全选 A）
> 状态：待验证假设，试点数据回放后方可作为验收依据

## 一、业务目标与验收

| 项 | 口径 |
|---|---|
| 学期总目标 | 每学期选课冲突 360 → 80；调课处理 3 天 → 1 天 |
| 试点验收 | 单专业试点：时空冲突识别率 100%（按**冲突事件数**计数）；人工调整工时下降 30% |
| 观察窗口 | 开学周日均 120 个调整请求；每学期 420 门次课程 |
| 预算约束 | 首期 10 万元（含集成、培训、验证），收益须扣除维护与人工复核成本 |
| 决策链 | 教务主任立项推动；教学质量专员可否决上线；专业课程负责人参与结果验收 |

## 二、范围与边界（红线）

- **只做**：冲突前置提示、冲突问答、调课调整草稿、交接单据管理、审计留痕、试点指标统计
- **禁止**：自动选课、自动改成绩、自动修改培养计划；接口只读，AI 无任何写真实教务数据的权限
- **草稿机制**：调整草稿仅由**排课专员**人工确认后才生成正式记录；建议必须显示原记录与待确认字段
- **数据边界**：学生选课数据**不落本地库**，查询时实时透传教务接口；本地仅存会话、日志、知识库

## 三、数据接入（评审结论：真实 API + 官方映射表）

- 教务系统 / 场地预约 / 学籍库：**真实只读 API** 实时查询，15 分钟增量同步周期，超期标「待刷新」
- 课程新旧代码：使用教务系统工程师提供的**官方映射表**，系统只读，不自行维护
- 接口中断：继续使用带时间戳的上一份只读快照，结果标注「基于 xx 时间快照，暂未更新」；照常校验
- 脏数据：歧义记录不进入自动推荐；修复由官方渠道负责

## 四、角色与权限（RBAC）

| 角色 | 能力 |
|---|---|
| 学生 | 冲突问答、选课前冲突查询、查看冲突提示（纯只读） |
| 辅导员 | 查看交接单据、现场异常登记 |
| 排课专员 | 知识库维护、**草稿确认**、冲突回放验证、交接分派 |
| 教学质量专员 | 审计记录、停止条件判定、**试点上线否决权** |
| 教务主任 | 试点指标查看、超时升级接手 |
| 专业课程负责人 | 服务结果验收 |

- 交接单据必含：业务编号、版本、状态、未解决事项、接手人；**对方确认接手才算完成**
- 超时**自动升级**教务主任并通知

## 五、关键技术决策（评审结论）

1. 口径：冲突按事件数计数；统计模块按此实现，预留口径配置位
2. 校验降级：快照数据照常参与校验，所有建议携带快照时间戳，三端（学生/辅导员/排课）统一展示
3. 确认链：学生端只读，草稿确认权仅在排课专员
4. LLM：低成本档模型（可替换供应商），冲突校验核心逻辑**不依赖 LLM**（纯代码规则引擎），LLM 负责意图理解与结果解释
5. 知识库：现成制度文档（markdown/PDF）入库做 RAG；先修关系同时做结构化规则校验，保证识别率
6. 暂停开关：管理后台提供「暂停试点」全局开关，一键降级为纯 RAG 问答或完全下线

## 六、人工兜底四类必转场景

1. 实训室维护占用但排课表仍标可用（场地占用类）
2. 资料缺少依据
3. 两个版本规则冲突
4. 关键系统不可用

→ 均需标注：触发原因、接手人、确认时间

## 七、审计与留存

- 每次建议保留：业务编号、资料版本、事实引用、建议结果、人工改动、签核人
- 审计可重建「教学计划 → 排课 → 选课 → 冲突校验 → 调整 → 名单确认」单次处理
- 评价记录暂留 90 天，期满由教学质量专员复核删除或归档
- 不记录账号口令与不必要的个人信息

## 八、试点停止条件

触及即暂停试点、负责人复盘；教学质量专员拥有否决权（具体清单由其牵头在试点前定稿）。
