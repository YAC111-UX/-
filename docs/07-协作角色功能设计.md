# 知行职业学院排课选课助手 · 协作角色功能设计（辅导员转报备 + 专业负责人核校验收）

> 版本：v1.0（2026-11-06）｜阶段 8｜依据：01-需求清单角色表、seed.py 角色注释（counselor 学生转报备/答疑转办；program_leader 培养方案核校/服务结果验收）
> 目标：让两个"业务侧协作角色"（辅导员、专业课程负责人）真正进入系统闭环，而非只留账号——**辅导员可转报备并复用阶段 7 交接单流转，专业负责人可核校培养方案并验收处理结果**，全程留痕。

## 一、设计原则（3 条）

1. **报备即交接单**：辅导员的"学生转报备 / 现场异常登记"不新建状态机，直接生成 `handover_tasks` 单据派给排课专员——阶段 7 的认领/完成/超时升级闭环**零改造复用**，报备单天然可追踪（业务编号、接手人、确认时间全齐）
2. **协作角色不进管理后台**：需求约定"学生/辅导员不进 /admin/*"。新增独立工作台 `/workbench`，登录态与后台共用同一 JWT
3. **聊天页身份打通**：`/api/chat` 阶段 5 起已支持 `Authorization` 可选头（optional_user_id），本阶段在 index.html 加登录入口——辅导员登录后提问审计显示真实角色（替代"游客"），并解锁"转报备"按钮

## 二、功能与状态流

### 1. 辅导员：学生转报备 / 现场异常登记

```
聊天页（登录后）点「转报备」──┐
                              ├──▶ POST /api/co/reports ──▶ 生成 handover_task
工作台「现场异常登记」表单 ────┘         (creator=辅导员, assignee=排课专员,
                                         escalate_at=+24h, status=pending)
                                        ──▶ 排课专员在 /admin/handover 认领/完成
                                        ──▶ 超时自动升级教务主任（阶段 7 逻辑）
```
- 转报备：body 带 `session_id`，服务端**从库里取该会话最后一条用户提问原文**（不信任前端传参，防篡改审计链）；前端只传补充说明
- 现场异常登记：body 传 `title` + `detail`（如"X102 实训室维护占用但排课表仍标可用"）
- 「我的报备单」：查 `handover_tasks.creator_id = 我`，联接手人姓名与当前状态，工作台展示

### 2. 专业课程负责人：培养方案核校 + 服务结果验收

```
工作台查看课程清单（5 门课 + 先修映射，读 data/mock/academic.json + rules/prerequisite）
   └─▶ 提交核校意见 {verdict: pass/issue, issues} ──▶ co_verifications 留痕
工作台查看已完成交接单
   └─▶ 提交验收 {verdict: pass/issue, comment}  ──▶ co_verifications 留痕
        ──▶ 管理端 /admin/handover 列表联查显示验收标记（已验收·通过/有问题）
```
- 核校与验收**只留痕、不判定**：发现问题走既有交接单流转，专业负责人不做修改操作（角色表定义"参与结果验收"）
- 允许对同一对象多次提交意见（追加留痕，列表取最新一条展示）

## 三、接口清单（新增 `app/api/co.py`，RBAC 复用 require_roles）

| 方法 | 路径 | 角色 | 说明 |
|---|---|---|---|
| POST | `/api/co/reports` | counselor | 新建报备（转报备/现场异常）→ 生成 handover_task，返回业务编号 |
| GET | `/api/co/reports` | counselor | 我的报备单列表（creator_id=我，带状态/接手人） |
| GET | `/api/co/program` | program_leader | 培养方案课程清单 + 先修映射（只读聚合） |
| POST | `/api/co/program/verify` | program_leader | 提交核校意见 `{verdict, issues}` 落痕 |
| GET | `/api/co/verify/history` | program_leader | 我的核校/验收历史（最新在前） |
| GET | `/api/co/acceptance` | program_leader | 已完成交接单列表 + 最新验收状态 |
| POST | `/api/co/acceptance/{task_id}` | program_leader | 验收 `{verdict, comment}` 落痕 |

- 错误码沿用 1001/1005；转报备会话无提问记录 → 1001
- 越权示例：scheduler 调 `/api/co/*` → 1005

## 五、验收标准（阶段 8 自测口径）

1. 辅导员登录聊天页提问 → 审计页该条消息角色显示"辅导员"（非游客）
2. 聊天页「转报备」→ 返回业务编号；排课专员在交接单页能搜到该单并走认领/完成闭环
3. 工作台现场异常登记 → 同样生成交接单；我的报备单列表可见状态变化
4. 专业负责人查看培养方案清单 → 提交核校意见 → 历史可查
5. 专业负责人验收已完成交接单 → 管理端交接单页显示验收标记
6. scheduler/quality/director 调 `/api/co/*` 全部 1005
7. E2E 冒烟覆盖 1~6
