# 知行职业学院排课选课助手 · 人工协作工作流设计（草稿确认 + 交接单闭环）

> 版本：v1.0（2026-11-06）｜阶段 7｜依据：02-架构设计（services/handover.py、draft.py）、05-Agent工具设计
> 目标：把阶段 6 产生的两类单据（调课草稿、人工兜底交接单）做成**可操作的人工闭环**——确认/认领/完成/超时升级，全程留痕可审计。

## 一、两个状态机

### 1. 调课草稿（drafts）

```
pending_confirm ──确认(confirm，仅排课专员)──▶ confirmed   （落正式回放记录关联）
       └────────驳回(reject，仅排课专员)──────▶ rejected
```
- 确认动作：drafts.status=confirmed、confirmed_by/confirmed_at 落库；同时回填 conflict_replay_records.draft_id + confirmed_by（审计链闭环：校验 → 草稿 → 签核人）
- 已终态（confirmed/rejected）的单据不可再次操作（错误码 1012）

### 2. 交接单据（handover_tasks）

```
pending ──认领(accept，被派人人本人)──▶ accepted ──完成(complete，填处理结果)──▶ completed
   └──────────超时未处理(escalate_at 到期)──────────▶ escalated（改派教务主任，重新进入待处理）
```
- 认领：仅派给本人（assignee_id = 当前用户）可 accept，落 accepted_at（满足需求"标注确认时间"）
- 完成：仅派给本人可 complete，必须填 resolution 处理结果（审计要求）
- 超时升级：`escalate_at` 已到期且 status 仍是 pending/assigned → status=escalated、escalated=1、改派教务主任（assignee_id 换人），重新等待认领
- 升级时机：**惰性检查**——每次查列表时先 sweep 一遍到期单据（试点期单机够用，免起定时任务）

## 二、接口清单（RBAC 均复用阶段 5 require_roles）

| 方法 | 路径 | 角色 | 说明 |
|---|---|---|---|
| GET | `/api/admin/drafts` | scheduler（全部）/ director（只读） | 草稿列表，筛选 status |
| POST | `/api/admin/drafts/{id}/confirm` | scheduler | 确认草稿 → 终态 + 回填回放记录 |
| POST | `/api/admin/drafts/{id}/reject` | scheduler | 驳回草稿（需填 reason） |
| GET | `/api/admin/handover` | scheduler / director | 交接单列表，筛选 status；查询前先执行超时 sweep |
| POST | `/api/admin/handover/{id}/accept` | 被派人本人 | 认领 → accepted |
| POST | `/api/admin/handover/{id}/complete` | 被派人本人 | 完成，body `{resolution}` 必填 |
- 错误码沿用：1005 无权限 / 1001 参数错误；新增 **1012 单据当前状态不允许该操作**

| 页面 | 路径 | 角色 | 功能 |

## 五、验收标准（阶段 7 自测口径）

1. 排课专员确认草稿 → drafts.confirmed_by 落人，conflict_replay_records.draft_id/confirmed_by 同步回填
2. 已确认草稿再次确认/驳回 → 1012；director 调 confirm → 1005
3. 驳回必须填 reason，否则 1001
4. 交接单被派人本人可认领（accepted_at 落库）；非本人认领 → 1005
5. 完成不填处理结果 → 1001；完成后单据状态 completed 且结果可查
6. 把 escalate_at 改到过去时间 → 查列表触发升级：status=escalated、改派 director、escalated=1
7. 两个新页面正常渲染，导航项按角色显隐（quality 看不到草稿确认页入口）
